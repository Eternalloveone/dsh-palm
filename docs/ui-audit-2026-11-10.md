# 手机端逐屏 UI 审查（2026-11-10，refactor/v2 现状）

> 目的：按"打开聊天先看到当前问题、回答和下一步动作"的目标，逐屏列出**现在实际长什么样、问题在哪、改法是哪一层**，作为接下来 UI 切片的执行顺序。
>
> 证据来源：`src/mobile/views/App.tsx` 的真实路由表、各屏组件源码、`src/mobile/styles/*.css` 的既有规则与 token、`docs/superpowers/specs/2026-11-09-reading-flow-ui.md`。**没有真机视觉证据的项一律标注"待视觉验收"**，不以单测冒充视觉通过。

## 真实路由清单（不是 18 屏稿）

`chat`（唯一会话页）/ `search` / `settings` / `appearance` / `approval` / `approval-mode` / `context` / `artifacts` / `artifact-summary` / `outline` / `diff` / `delivery`，外加抽屉（`SessionDrawer`）、配对页、dev 画廊 `/m/#dev/ui`。

## 执行顺序（每步一个可回退切片，先写失败测试）

1. **P4 结论卡四态**（聊天页，最影响"下一步动作"的可见面）：状态词表复用 `session/task-status.ts`，卡面四态 + 动作（重试/查看错误/展开过程）。
2. **聊天正文流层级**：过程组降级、纯问答轮不画回合头、正文/过程/元信息三级字号与间距固化到 token 级契约测试。
3. **composer / dock 窄屏**：入口折叠进「⋯」、dock 最大高度 + 内部滚动、队列/插入行高统一。
4. **SessionDrawer 分组**：三组标题 + 运行中行样式 + 顶部搜索。
5. **次级页统一**：审批/提问 → diff/文件 → 产物/大纲/上下文 → 设置/外观/配对。
6. **状态矩阵**：空/加载/离线/失败/键盘/窄屏 × 深浅，用截图矩阵（配对后可跑 `tools/mobile-visual/run.mjs`，本轮以组件测试 + 结构契约替代并记录待验项）。

## 本轮可验证的边界
