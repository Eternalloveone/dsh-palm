# 业界手机端布局调研（会话型 / 任务型应用）

> 说明：以下基于我对这些产品**当前形态**的了解整理，未逐版本核对；本轮联网检索返回的是词典类噪声，未采信。
> 目的不是抄，而是回答一个问题：**"工作区/仓库"该不该做成一级页面？**

---

## 一、五种主流形态

| # | 形态 | 代表产品 | 首页是什么 | 工作区/空间在哪 |
|---|---|---|---|---|
| **1** | **Chat-first（输入框即首页）** | ChatGPT、Claude | 一个输入框 + 最近会话 | 没有这个概念，或藏在侧边抽屉 |
| **2** | **Top switcher（顶部切换器）** | Slack、Notion | 内容列表 | **顶部一个 chip/下拉**，不是页面 |
| **3** | **Bottom tabs（底部标签）** | GitHub Mobile、Linear、Slack | 某个 tab 的内容 | 顶部 chip；tab 之间是并列的"目的地" |
| **4** | **Inbox-first（收件箱）** | Linear Inbox、GitHub Notifications | 需要你处理的事 | 作为筛选器 |
| **5** | **Projects/文件夹树** | Claude Projects、ChatGPT Projects、Cursor（桌面） | 项目列表 | **一级页面**，但只在"多项目并行"的桌面场景成立 |

### 关键观察

1. **几乎没有一个主流产品把"仓库/工作区"做成手机端的一级页面**。做成一级的只有 Projects 类（第 5 种），而它们的手机端都把 Projects 降权（Claude 把 Projects 放进侧边抽屉）。
2. **Chat-first 与 Bottom tabs 是当前最强的两个范式**：前者省层级，后者给"并列目的地"。
3. **Inbox-first 在"需要你决策"的产品里越来越常见**——AI agent 类应用天然有"等你批准/等你回话"的状态，正好是收件箱的语义。

---

## 二、dsh-palm 的特殊性（不能照抄的部分）

| 事实 | 后果 |
|---|---|
| 一个 workspace = 一个真实仓库，会话是"在该仓库上跑的任务" | 工作区**有真实语义**，不能像 ChatGPT 那样彻底取消 |
| 有长任务在跑（可跑几分钟） | 需要"运行中"常驻入口，不能只在列表里滚动找 |
| 有审批/提问需要人回 | 需要"待处理"聚合，否则用户不知道 agent 卡住了 |
| 产品定位：不是深度工作终端，复杂配置留桌面 | 手机上只做"看 + 回 + 批"，不做编辑 |

## 三、推荐形态：Chat-first + Top switcher + Bottom tabs（组合）

```
┌─────────────────────────────┐
│ dsh-palm ▾        运行中 ● 1 │  ← 顶部：工作区切换 + 运行中入口
├─────────────────────────────┤
│                             │
│   今天想做点什么？            │  ← 首屏核心：输入框（可直接发）
│   ┌───────────────────────┐  │
│   │ 给这个仓库加点测试…    │  │
│   └───────────────────────┘  │
│                             │
│  最近                        │
│  ● dsh-palm · 正在改 UI      │  ← 运行中置顶（可多张）
│    test_stylus      1 小时前  │
│    07.FEP           昨天     │
│                             │
├─────────────────────────────┤
│  对话      收件箱 ②      设置 │  ← 底部三标签
└─────────────────────────────┘
```

### 三个组件各自的来源

| 组件 | 抄谁 | 为什么 |
|---|---|---|
| 输入框即首页 | ChatGPT / Claude | 最高频动作"发一句话"变成 0 步 |
| 顶部工作区 chip | Slack / Notion | 保留工作区语义，但不占一层 |
| 运行中置顶卡 | GitHub Actions / Linear | 长任务要能一眼看到、一点回到现场 |
| 底部收件箱 tab | Linear Inbox | 审批/提问集中，避免"agent 卡住没人知道" |
| 最近会话分组 | ChatGPT / Claude | 今天/昨天/更早，比"按工作区分组"更符合人的记忆方式 |

## 四、三个可对比的备选

| 备选 | 首页 | 优点 | 缺点 |
|---|---|---|---|
| **A 组合式（推荐）** | 输入框 + 最近 + 运行中 | 0 步发消息、1 步回现场、待办有去处 | 首屏信息多，需要克制 |
| **B 纯 Chat-first** | 只有输入框 + 最近 | 最简洁，学习成本最低 | 工作区、运行中、审批都要藏进抽屉，找不到 |
| **C Inbox-first** | 待处理清单 | "有事才来"最省心 | 平静期首页是空的，不利于主动发起 |

## 五、聊天页的业界共识

| 做法 | 谁在用 | dsh-palm 对应 |
|---|---|---|
| 消息流固定 `1fr`，头尾不挤压 | 全部 | 队列坞并入输入框上方一行 |
| 工具调用默认折叠成一行摘要 | Cursor / Claude Code | 已有折叠模型，改成默认收起 |
| 流式输出时只有末条更新 | 全部 | 对应 memo 分层（P4） |
| 底部输入框吸附键盘上沿 | 全部 | 已有 `useKeyboardInset` |
| 长按消息弹菜单 | 微信 / Telegram | 已有 `useLongPress` |

## 六、结论

**当前 dsh-palm 的问题不是"设计不好看"，而是"把工作区当成了首页"。**

业界同类产品在手机端的一致做法：**工作区降级为顶部切换器，首页让位给"发消息 + 最近会话"，把"要你处理的事"单独给一个入口。**

推荐采用 **A 组合式**：Chat-first 首页 + 顶部工作区 chip + 底部三标签（对话 / 收件箱 / 设置）+ 运行中置顶卡。

落到架构：首页是 **L4 新实现**（换 manifest 一行），三标签是 **L3 布局**（插槽：top / main / tabbar），皮肤是 **L1/L2**。三者互不牵连。
