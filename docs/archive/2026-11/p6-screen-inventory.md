# P6 屏幕盘点：规范 18 屏 vs 当前实现

> 目的：**先看清差距再动手**。规范里的 18 屏有一半目前不是"页面"，而是浮层/弹窗或干脆没有。
> 不做盘点直接迁，会写出一堆没人走的空页面。
>
> 证据来源：`src/mobile/views/*.tsx`（顶层屏）、`views/**/*-sheets.tsx`、`views/**/*-overlays.tsx`、
> `components/sheets.tsx`、`App.tsx` 的 `Route` 联合类型。

## 一、结论先看

| 分类 | 数量 | 说明 |
|---|---|---|
| ✅ 已是独立页面 | 5 | 首页、会话列表、对话、设置、子会话 |
| 🟡 页面存在但不达标 | 3 | 空态/失败态/完成态：逻辑有，结论卡与状态条未按规范定版 |
| 🔴 现在是浮层 | 7 | 审批、模型、批准方式、上下文、产物、diff、回合大纲 |
| ⚫ 完全没有 | 3 | 搜索独立页、产物摘要、归档、外观（设置项在浮层里，无独立页） |

**迁移量最大的是 🔴 那 7 个浮层**：它们已有功能与数据，缺的是"页面外壳 + 路由"。

## 三、迁移顺序（按"用户能感知"排序）

1. **④ 审批详情**——最影响安全感的浮层，改成页面后返回落点天然正确（栈已有）。
2. **⑩ 单文件 diff**——浮层里看代码体验最差，`170-diff.css` 已备好。
3. **⑤ 模型与思考**——设置类，改动小、回归快。
4. **⑭ 外观**——三皮肤切换，能立刻验证令牌体系。
5. **⑫ 回合大纲 + ⑧ 产物列表**——两者共用"按轮聚合"数据。
6. **⑦ 上下文占用 / ⑥ 批准方式 / ⑨ 产物摘要 / ⑮ 归档**——新页，工作量集中。
7. **② 搜索独立页**——最后做，内联搜索已够用。

## 四、每屏迁移的固定动作（模板）

1. `Route` 加一个 kind（`routeKeyOf` 同加）；
2. `layouts/screens.ts` 加一份排布（或复用已有）；
3. 新视图文件用 `SlotLayout` 渲染，**不留行内样式**；
4. 浮层里的数据获取**原样复用**（不重写业务逻辑）；
5. 加 `*.test.tsx`：渲染 + 返回落点 + 空态；
6. 跑 typecheck → build → 全量测试 → 预算 → **删掉旧浮层的入口**。

## 五、不做什么

- **不新增 18 个路由字符串常量表**：`Route` 联合类型 + `routeKeyOf` 已经够；
- **不把 sheet 全删光**：输入法面板、选择器这类"打断式"交互仍用浮层，规范只要求
  "可独立存在的看/改页"变成页面；
- **不做页面转场动画**（P7 才做），本轮只保证路由与返回正确。
