# 手机端「运行中」页显示子代理 —— 设计

- 日期：2026-09-16｜版本：待定（随当前未提交批次一起发布）
- 范围：`packages/dsh-palm`（手机面 `/m`）
- 状态：**v3 已实现（2026-10-28 重做），`RunOverviewView` 29 项 / `run-detail` 12 项 / `recent-finished` 9 项相关测试通过，`tsc -b` 干净**
- 后续版本：v3 见本文 §5；§1–§4 保留 2026-09-16 的原始设计与当时的取舍
- 相关文件：`src/mobile/views/RunOverviewView.tsx`、`src/mobile/views/SubChatView.tsx`、`src/mobile/run-detail.ts`、`src/mobile/recent-finished.ts`、`src/mobile/subagent-tree.ts`、`src/mobile/run-status.tsx`、`src/mobile/views/ChatView.tsx`、`src/mobile/mobile-styles.ts`、`src/mobile-log-source.ts`

## 0. 目标

手机上**不打开会话**也能看出"哪个会话正在等哪个子代理"。

之前的三处运行态各有盲区：

| 位置 | 之前显示什么 | 盲区 |
| --- | --- | --- |
| 会话列表行 | 圆点 +「进行中」 | 纯布尔，无详情 |
| 聊天内运行状态条 / 抽屉 | 任务 n/m · 后台任务 n · 子代理 n | **只在当前打开的那个会话里**才有数据 |
| 「运行中」页 | 后台任务行 + 运行中会话卡 | 只有**后台**子代理（`session/jobs` 里的 `kind:'subagent'`）；前台子代理不是 job，页面上只写「回合中」 |

关键事实：前台子代理没有 job 生命周期（父会话的 turn 一直开着等它），宿主也不把 `host/session-status` 推给手机，所以手机端唯一的来源是 `subagents.list` 轮询。

## 1. 范围

**做**

1. 「运行中」页对**正在运行的会话**轮询 `subagents.list`，在会话卡里显示运行中的子代理。
2. 顶部总览加子代理计数：`2 个会话正在运行 · 1 个后台任务 · 2 个子代理`。
3. 同一件事不重复显示：后台委派的子代理本来既是 job 行又是子会话，子代理行覆盖得住时就不再单列那条 job 行。

**不做**（YAGNI）

- 会话列表行徽章加子代理：列表是首屏性能敏感区（骨架屏 / IndexedDB 缓存 / content-visibility），每行一个请求不划算，行宽也放不下。
- 点进子代理会话看内容：子代理会话在 `mobile-api` 里被有意过滤（`origin: 'subagent'`），放开是另一档改动。
- 手机端创建 / 操控子代理：委派由宿主 agent 决定，手机只做展示。

## 2. 设计

### 2.1 数据来源（有界轮询）

- 只对**live 会话**发请求，最多 `SUBAGENT_SESSION_MAX = 4` 个（防止会话一多就放大请求数）。
- 页面打开期间每 `SUBAGENT_POLL_MS = 8000` 一次；**live 集合变化时 effect 重挂**（新会话开始 / 旧会话结束都能跟上）；一个 live 会话都没有时**完全不发请求**。
- 该常量从 `ChatView.tsx` 搬到 `subagent-tree.ts`（聊天与全局页共用，避免两处各写一个数字）。
- 新增 `fetchSubagents()`：宿主答了 → 数组（可能是空，代表"没有子代理"）；调用失败 → **`undefined`（未知）**。`fetchSubagentsFlat()` 保留原语义（失败返回 `[]`），聊天路径不受影响。

区分"答了但为空"和"没答上"是必需的，见 2.3。

### 2.2 界面

会话卡（运行中的卡才显示）自上而下：

```
[● 运行中] 会话标题
           会话 s-live
子代理
● 整理记忆 · 运行中
● 跑真机回归 · 运行中
… 还有 2 个子代理            ← 超过 SUBAGENT_VISIBLE_MAX = 3 折叠
后台任务                     ← 有子代理分组时才显示该小标题
● 跑测试 · 开始于 09:41
```

- 行样式直接复用聊天抽屉里的 `SubagentRow`（`chat-subagent-*`），**零新增行样式**；只加了一个 `.runov-subgroup-title` 小标题。
- **只列运行中**的子代理：这一页的定位是"现在在干什么"，空闲的不占屏。
- 页首计数只统计被轮询到的会话（即已知的那部分），拿不到就不显示这一段，不猜。

### 2.3 去重（同一件事只出现一次）

后台委派的子代理会同时是：一条 `session/jobs` 行（`kind: 'subagent'`，带开始时间）和一个子会话（`subagents.list` 里有它）。两条并排显示就是同一个东西出现两次。

规则：**运行中的 subagent 类 job 行，在子代理行覆盖得住时隐藏**——

```
hideSubagentJobs = 运行中的 subagent job 数 > 0
                && 运行中的子代理行数 >= 运行中的 subagent job 数
```

- 用 `>=` 而不是 `> 0`：宿主只答了一半（比如 1 个子代理行、2 条 job 行）时**宁可不隐藏**，绝不因为信息不全而藏掉正在跑的工作。
- 失败 / 未答（`undefined`）一律不隐藏，行为与改动前完全一致。已结束的 job 行不受影响（那部分子代理是空闲的，子代理分组里本来就不显示）。

### 2.4 边界

- 请求失败**静默降级**：页面不报错、不空白，只是退回"只有后台任务行"的旧样子。
- 离开页面即停轮询（effect cleanup 取消 in-flight 回填 + `clearInterval`）。
- 不碰会话列表、不碰首屏路径、不动 `mobile-api` 契约（`subagent.list` 是既有接口，DSH 版本无关）。

## 3. 测试

`RunOverviewView.test.tsx` 新增 6 项（原有 8 项保持通过）：

1. 显示 live 会话的运行中子代理，超过 3 个折叠、点开展开，页首计数正确。
2. 只列运行中的（空闲子代理不显示）。
3. 子代理行覆盖得住时，同名的 subagent job 行不再重复出现。
4. 宿主没答（reject）时保留 job 行，且不显示子代理分组。
5. 非运行中的会话**完全不发请求**（`subagentsList` 未被调用）。
6. 轮询上限：5 个 live 会话只问前 `SUBAGENT_SESSION_MAX` 个。

## 4. 后续（未做，需要时再评估）

- 若卡片信息仍显得多，可把"已结束的子代理"折叠进现有的「n 个已完成」。
- 若要"子代理到底做了什么"，需要放开子代理会话 + 只读回放，属于独立设计。

## 5. v3：卡片说清"在干什么"、子代理可点、刚结束驻留（2026-10-28）

### 5.1 用户当时报的三件事

| 反馈 | 当时的实际表现 |
| --- | --- |
| 「信息有限」 | 卡片只有标题 + `回合运行中 / 正在生成回复 · 点击进入查看`；跑了多久、第几步、在跑什么命令、在哪个工作区，全都看不到 |
| 「跑完没法立刻定位是哪个」 | `turn/end` 一到卡片直接从列表里消失，没有任何"刚才是它跑完了"的痕迹 |
| 「过程条在跑却显示已完成」 | 长回合的 `turn/start` 被挤出尾部窗口、窗口里只剩上一轮的 `turn/end` 时，宿主答"收工了" |

### 5.2 版面（v3 定稿）

```
正在运行  2 个会话 · 1 个子代理 · 1 个后台任务 · 跨全部工作区
┌───────────────────────────────────────────────┐
│ ● 梳理测试函数逻辑                          › │
│   pnpm test · 第 7 步 · 已跑 12分04秒         │
│   demo-workspace · 3 秒前有活动     │
│   ├ ● 梳理 SessionListView 的翻页测试  2分10秒 › │
│   ├ ● 核对 mobile-api 的分派分支        41秒   › │
│   └ 另有 1 个后台任务                        › │
└───────────────────────────────────────────────┘
刚结束  2                                    全部清空
✓ 互容CDMA数据仅显示一行   已完成 · 8分39秒 · 2 分钟前
⚠ 手机端过程条计时排查     出错退出 · 2分10秒 · 6 分钟前
```

三条版面规则（都是真机上被反馈过的）：

1. **统一 14px 图标列**：状态点 / ✓ / ⚠ / ■ 各占一列，标题与下面每一行从同一条竖线开始，不再形成两栏错位。
2. **一行标题 + 两行元信息**：动作（工具名 + 参数摘要）· 第 N 步 · 已跑；工作区 · 最近活动 · 子代理数。
   一行塞不下就换行，不截断标题（标题是"是哪一个会话"的唯一凭据）。
3. **后台任务不再是分组**：卡片底部一句「另有 N 个后台任务 ›」，展开才列出；子代理那份 job 行被子代理行取代后不重复。

### 5.3 数据来源（不加宿主 RPC）

| 字段 | 来源 | 刷新 |
| --- | --- | --- |
| 动作 / 第 N 步 / 真起点 / 最近事件 | 每个在跑会话一页 `mobile.logTail`（宿主已折叠好） | 6 秒，仅本页可见 |
| 工作区名 | 花名册 `session.cwd` 尾段 | 进入页面时一次（分页落地即渲染） |
| 子代理列表 / 是否在跑 / 已跑 | `subagent.list`（宿主按子会话日志边界补运行态） | 8 秒 |
| 刚结束 | 本地账本 `recent-finished.ts`（localStorage，30 分钟 / 最多 8 条） | 收工即写 |
| 运行集合 | mux 的 `runningSessionsSnapshot` + `refreshRunning()` 校准 | 帧驱动 + 30 秒 |

`run-detail.ts` 是纯函数：一页尾页 → `{ action, actionHint, step, turnStartAt, lastEventAt, turnOpen, summary, durationMs, status }`，
所以这些字段在单测里可以逐条钉住，不需要渲染整页。

### 5.4 状态判定（这次修复的核心）

「这一轮还开着吗」以前只有一个来源：窗口里最后一条边界。它有两个坑，都是真机踩出来的：

| 现场 | 旧判定 | 现在 |
| --- | --- | --- |
| 长回合，`turn/start` 被挤出 48 帧窗口 | 窗口里没有边界 → 退回"日志三分钟内有动静"启发式 | 按轮号从日志里补回真起点（帧 2048 / 字节 2 MB），并且把它当作"开着的回合" |
| 窗口里最后一条边界是**上一轮**的 `turn/end` | 判"收工了" → 过程框定格成已完成，而命令还在跑 | 只要 `turn/end` 之后还有**回合活动类**事件，就判"新一轮在跑" |
| 收工后补写 `job/registered`、`job/settled`、`agent/inbox/spliced` | 会被当成"新一轮在跑"（误点亮） | 这些记账事件不算，只有 `user/message`、`assistant/*`、`tool/*`、`step/*` 等算 |

客户端侧另外两条：

- **收工定格不会往回跳**：`noteOpenTurnStart` / `noteTurnStart` 只对窗口里最新的那一轮生效，`applyTurnEnd` 优先用宿主给的真起点，
  旧回合的 `turn/end` 不会顺手把外部锚点吃掉（真机：8 分 39 秒的一轮曾定格成 3 分 22 秒）。
- **跑完了要退场**：花名册的 `running` 会撒谎，所以尾页说 `turnOpen === false` 就立刻退场，另有 30 秒 `refreshRunning()` 兜底。

### 5.5 子代理只读会话页

- 子代理**就是会话**（宿主按 `sessionId` 落盘），所以内容直接读日志；`mobile.readChat` 走花名册/投影那条路会拒绝子会话，只读页只用 `mobile.logTail`。
- 只读：底部没有输入框，页脚固定「只读视图 · 子代理不能从这里接收新消息」，只留「回到运行中」。
- 展示：顶部写明"来自哪个父会话 + 子代理标签 + 当前状态/已跑"，正文按"任务 → 工具步骤 → 回答"排。
- 子会话自己也会 emit `turn/start`，于是它同样进运行集合 —— 现在按子代理 id 过滤，不再顶出无名卡。

### 5.6 已知限制

- 只读页只取尾部 40 行、5 秒刷新，**不能往上翻历史**（子代理跑很久时看不到开头）。
- 「刚结束」只在 `/m/` 开着时记账；手机没开页面时跑完的会话不会自己进账本（正解需要在宿主侧维护"最近收工"，要改契约 + 重启）。
- 记账靠 localStorage：换设备/清缓存即丢；上限 8 条 / 30 分钟，没有"查看全部"。
- `subagent.list` 的 `parentAvailable` / `hasChildren` 仍是占位值（只读一层目录，不展开子孙树）。
- 收工状态在缺少 `turn/end` 帧时靠"最后一条助手行的工具状态"推断，可能把"工具报错但回合正常结束"记成出错。
