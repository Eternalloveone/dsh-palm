# 移动端「画面自洽」不变量

> 这份文件是**规则**，不是复盘。它回答一个问题：**什么样的画面永远不许出现在手机上**，
> 以及这些规则由哪一层守着。

## 为什么要它

真机上反复出现同一类 bug，症状各不相同、病根是同一个：**画面里各块各判各的**。

- 2026-11-01「会话还没结束就冒出交付结果卡」
- 2026-11-14 19:52「新建的空会话里挂着一张上一场的交付卡，下面紧跟『还没有消息』」
- 同类：空会话顶部一个永远点不出东西的「加载更早的消息」、卡在一行正文都没有的屏上

每次都是"补一条判断"修好的，所以每次都换个入口再来一遍。根治的办法是把"这一屏必须成立"
写成**可执行的断言**，让它在 CI 里红，而不是等用户截图。

## 四条不变量（违反即失败）

| # | 不变量 | 为什么 |
|---|---|---|
| 1 | **有卡 ⇒ 屏上一定有正文** —— 交付卡不能是屏幕上唯一有内容的东西 | 卡是"这一轮的结果"，没有正文的结果卡就是在替宿主编故事 |
| 2 | **卡与空态互斥** —— 「还没有消息」和交付卡不同屏 | 两者同时成立只有一种解释：卡不是这一场的 |
| 3 | **「加载更早」不挂在空列表上** —— `hasOlder` 可见 ⇒ `rows > 0` | 宿主对空会话也会答 `hasMore=true`（窗口前面有 `session/start` 之类系统事件），空列表上的分页按钮永远是死的 |
| 4 | **每一块都能说出自己属于哪一场** —— 尾部卡带 `data-owner=<sessionId>`，必须等于当前会话 | 跨会话串味时，这是唯一能在 DOM 里一眼看出来的证据 |

## 谁来守

| 层 | 位置 | 守什么 |
|---|---|---|
| 数据 | `session/deliveries.ts`（`turnKeyOf` = `sessionId#turn`）、`session/chat-snapshot.ts`（`createScopedStore`） | 按会话分槽 + **强身份**：写入带算它时的会话 id，读取按会话过滤（`latestDeliveryOf(records, sessionId)`） |
| 渲染 | `views/chat/components/chat-rows.tsx`（`deliveryVisible`） | 空列表不挂卡、不挂分页入口 |
| 宿主 | `chat-window.ts`（`pageOf` / `before`） | **空页不答 `hasMore`**：零行的页不许声称"还有更早" |
| 单元 | `chat-rows-delivery-gate.test.tsx`「画面自洽」组、`deliveries.test.ts`「两场同一个 turn 号」、`chat-window.test.ts`「空页不答 hasMore」 | 四条不变量 + 强身份，确定性、毫秒级 |
| 架构 | `platform/render-purity.test.ts` | **`useMemo` 里不许写 `ref.current`**：React 会丢掉渲染结果，ref 的写入却留下 —— 单槽缓存 + 渲染期写 = 这一整类事故 |
| 真机 | `tools/mobile-verify/cases/coherence.mjs`（`--groups=coherence`） | 进会话 / 换会话 / 新建会话三条路径，每 120ms 采一帧、连续 1.6 秒，坏帧即失败 |

## 怎么用（下次再遇到这类问题）

1. 先问：**它违反的是上面哪一条？** 四条都套不上，说明是需要新增的第五条 —— 那就加一条。
2. 修在**数据层**（谁的数据、属于哪一场），不要修在"这个入口的判断"上。
3. 同时补两处：单元断言（确定性）+ 真机断言（竞态窗口）。只补真机用例会飘，只补单元用例会漏路径。
4. 新增缓存/派生表，一律用 `createScopedStore(limit)`，不要手写 `Map` + 淘汰循环。

## 当前边界（已知未做）

- **行模型**（`render/messages.ts` 的 turn/step 键、合并/替换）仍按本场内的 turn 号工作：
  行状态本身住在按会话分槽的 store 里，所以没有串场，但它的键不再做"跨会话比较"。
  真要全链路强身份，得把 `RenderMessage` 的合成 key 也换成 `turnKey`（会动合并/锚点，单独排期）。
- 宿主 `session.history` 仍会返回 `hasMore=true` 而折叠后零行；`chat-window` 已经在出口
  归一化成 `false`，但 `mobile-log-source` 的日志尾页那条通道没有同样的归一化（那条路
  客户端有第二道门兜着）。
