# 手机端 UI 重新设计方案（布局重做）

> 现状实测：首页是**工作区列表**，进聊天要 3 步（工作区 → 会话 → 聊天）；
> 首页可见元素里有「工作区 / 固定 / 最近访问 / 运行中 / 三步上手」五组。
> 对"只想接着上次继续聊"的人来说，这个首页不回答他的问题。

---

## 一、三个候选方向（先选方向，再谈像素）

### 方向 A：会话优先（把工作区降级为筛选器）

```
┌─────────────────────────┐
│ 最近            [工作区▾] │  ← 顶部一行：工作区变筛选器
├─────────────────────────┤
│ ● dsh-palm   3 分钟前    │  ← 直接是会话，按最近排序
│   test_stylus  1 小时前  │
│   ...                   │
├─────────────────────────┤
│         [＋ 新会话]      │
└─────────────────────────┘
```

| | |
|---|---|
| 进聊天 | **1 步**（原 3 步） |
| 适合 | 日常"接着上次继续"占 90% 的场景 |
| 代价 | 工作区不再有独立首页，多工作区用户要靠筛选器 |
| 改动面 | 首页重写（L4）+ 会话列表复用（L3 布局） |

### 方向 B：首页双区（运行中置顶 + 最近会话）

```
┌─────────────────────────┐
│ 运行中 ● 1              │
│  ┌───────────────────┐  │
│  │ dsh-palm · 正在改 UI│  │  ← 卡片，点一下回现场
│  └───────────────────┘  │
├─────────────────────────┤
│ 最近会话                │
│  dsh-palm      3 分钟前  │
│  ...                    │
└─────────────────────────┘
```

| | |
|---|---|
| 进聊天 | 1 步（运行中）/ 2 步（历史） |
| 适合 | 经常有长任务在跑 |
| 代价 | 首屏更密，需要好的分区与留白 |
| 改动面 | 首页重写 + 运行中卡片组件 |

### 方向 C：保持三层，只重做视觉

| | |
|---|---|
| 进聊天 | 仍 3 步 |
| 适合 | 工作区是核心心智模型 |
| 代价 | 结构问题没解决，只换了皮 |

---

## 二、推荐：方向 A（会话优先），理由

1. **它解决的是"我不懂怎么用"的根因**：首页不再要求你先理解"工作区"这个概念。
2. **高频路径从 3 步降到 1 步**，且不违背 v3 的产品定位（单页状态机、两步可达）。
3. **工作区没有消失**，只是从"一层页面"变成"一个筛选器"，多工作区用户仍可用。
4. **改动可复用现有组件**：会话列表、搜索、筛选已经存在，主要是重排（L3）+ 首页重写（L4）。

---

## 三、聊天页同时重排（L3 就能做，不动逻辑）

| 现状问题 | 新布局 |
|---|---|
| 顶部栏 + 消息 + 输入框 + 队列坞四段堆叠，屏幕矮时消息区被压 | 队列坞**并入输入框上方一行**，可折叠；消息区固定 `1fr` |
| 工具调用卡片占高 | 默认折叠为一行摘要，点开才展开（L2 密度变体） |
| 底部安全区与键盘 | 沿用现有 `useKeyboardInset`，只改容器结构 |

## 四、落地路径（先出图，再上代码）

| 步 | 做什么 | 产出 | 工时 |
|---|---|---|---|
| **D0 诊断** | 量化现状：3 步路径、首屏信息密度、9 屏截图归档 | 一页诊断 | 0.5 天 |
| **D1 出图** | 方向 A 的 3 张关键屏（首页 / 会话 / 聊天）静态 HTML 稿，真机尺寸 | 可点击原型 | 1 天 |
| **D2 定规范** | 间距/字号/圆角/颜色梯度定成 token（L1），密度与形态定成 recipe（L2） | token 补丁 | 1 天 |
| **D3 两屏原型** | 用真实数据把「首页 + 聊天」跑起来，走 `data-layout` + `data-skin` | 可运行原型 | 2 天 |
| **D4 铺开** | 其余 7 屏按同一套 L1/L2/L3 迁移 | 全站一致 | 3 天 |
| **D5 验收** | 9 屏 × 皮肤截图矩阵 + 真机冒烟 + 路径步数验证 | 验收报告 | 0.5 天 |

**合计 8 天**，与 v3.2 的 P1.5/P2 共用同一套机制，不重复投入。

---

## 五、和架构方案的关系

| 你要的 | 由谁提供 |
|---|---|
| 换配色 | L1 token + `data-skin` |
| 换组件形态/密度 | L2 recipe |
| **换布局排布** | **L3 slots + layout spec** |
| 换整屏结构（如首页改为会话优先） | L4 新屏幕实现 + manifest 换 `load` |

**所以：先有 v3.2 的 L1/L2/L3，重做 UI 才是"配置 + 少量新实现"，而不是又一次大改。**
