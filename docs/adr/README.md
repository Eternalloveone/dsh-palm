# ADR 目录 · 架构决策记录

> 这个目录只放**做过就不好改、改了会让别人踩坑**的决定。不是会议记录，也不是教程。
>
> 每条 ADR 回答三个问题：**当时什么情况**（Context）、**选了哪条**（Decision）、**代价是什么**
> （Consequences）。最后一条最重要——只写好处的不叫决策，叫宣传。

## 什么时候该写一条

| 该写 | 不用写 |
|---|---|
| 引入/取消一个分层（如"薄表现层 + 六内核"） | 改个函数名 |
| 定协议形状（wire v1 帧、握手降级） | 加一个 CSS 类 |
| 加一道门禁（架构断言、预算只降不升） | 修一个 bug |
| 明知有例外却决定留（缓存例外清单） | 换一个库版本 |

## 怎么加一条

1. 复制 `template.md`，编号取当前最大 +1，文件名 `NNNN-短横线标题.md`。
2. `状态` 只能是：提议 / 已接受 / 已废弃 / 被 NNNN 取代。
3. 在下面的**索引表**里加一行（就是上面那张表）。
4. 如果这条决定让某个旧 ADR 失效，**去改那条 ADR 的状态**，别只在新的里写一句"以前不对"。

## 复查

每个季度（或每次大版本前）拿 `pnpm verify` 跑一遍，看哪些"已接受"其实已经
不成立——特别是那些**当时权衡过、后来前提变了**的（例如"先不做虚拟列表"在列表涨到
几千行时就不成立了）。
