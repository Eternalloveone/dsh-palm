# 0002 · wire 帧形状锁定 + 版本握手 fail-closed

- **状态**：已接受
- **日期**：2026-11-07
- **影响范围**：`src/mobile/wire/`、宿主侧帧发送方
- **相关**：`wire/version.ts`、`wire/frames.ts`、`wire/handshake.ts`、`wire/__snapshots__/`

## 背景

移动端与宿主之间走 mux 长连接，帧是**裸 JSON 对象**，靠 `type` 字段区分，共 18 种。
重构前没有任何形状约定：

- 宿主多塞一个字段、少塞一个字段，移动端要么静默忽略、要么在某个深层 `props.x.y` 处
  `Cannot read property of undefined`——**报错点离真因很远**。
- 前端先上线、宿主后上线（或反之）时，双方对同一个 `type` 的理解可能已经不同，没有任何
  握手，只能靠"用户反馈某个页面白屏"发现。
- 18 种帧没有任何清单，谁也不知道"还有哪些 type 存在"。

## 决定

1. **`WIRE_VERSION`**：单一整数，任何破坏性改动 +1。
2. **帧清单进代码**：`WIRE_FRAME_TYPES` 列出全部 18 个判别式，并用**编译期断言**保证
   "清单里没有多余的、也没有漏掉的"（`NoFrameMissingFromList` / `NoExtraFrameInList`）。
   加一种帧而忘了登记，`pnpm typecheck` 就红——不靠人记。
3. **形状快照**：`frames.test.ts` 对每种帧断言**顶层键集合**，快照进仓。改形状必须显式
   更新快照，diff 里一眼能看到"哪种帧动了"。
4. **握手 fail-closed**：`planHandshake(hostVersion)` 在版本不一致时返回
   `{ enabled: false, degraded: true }`，**降级到轮询**而不是硬连。宿主版本更高也一样降级
   （因为不知道它改了什么）。

## 代价

- **每次改帧要多做两步**：登记判别式、更新快照。改一个小字段也要走一遍。
- **快照是行为契约**：谁嫌麻烦直接 `-u` 更新，就等于把契约删了。规矩是：**更新快照必须在
  提交说明里写清为什么这次形状变化是安全的**。
- **版本号会被用来做兼容分支**：一旦开始写 `if (hostVersion >= 3)`，就会滑向"永远兼容所有
  旧版本"。当前策略是**不做兼容分支**，不一致就整体降级。
- **握手只覆盖"版本对不对"，不覆盖"字段对不对"**：同版本但字段类型变了，握手看不出来。
  这一层靠形状快照 + 测试兜。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 上 protobuf / JSON Schema 校验 | 移动端要压体积（当前 `mobile.js` 24 KB gzip），运行时校验器成本高；编译期断言 + 快照已能拦住 90% 的错 |
| 每个帧带独立版本号 | 18 个版本号要各自维护兼容矩阵，比一个全局号复杂得多；全局号不一致就整体降级的代价可以接受 |
| 不做握手，靠 404/报错自然暴露 | 移动端已缓存的旧包会连上新宿主，症状是"某个页面白屏"，排查成本远高于一次握手 |
