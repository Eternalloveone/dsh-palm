# 0003 · 数据层按域拆分，跨域依赖下沉到中间层

- **状态**：已接受
- **日期**：2026-11-07
- **影响范围**：`src/mobile/api.ts`、`src/mobile/data/**`、`src/mobile/mobile-types.ts`
- **相关**：`src/mobile/data/impl/*`、`src/mobile/architecture.test.ts`

## 背景

`api.ts` 曾是一个 **1,488 行 / 73 个端点**的文件。真正麻烦的不是行数，而是它是**三样东西的
混合物**：

1. 端点函数（73 个，分属 8 个业务域）
2. 时限常量与共享缓存状态（`PREFERENCES_TTL_MS`、`workspaceRosterCached`…）
3. 跨端点共享的类型（`ChatPage`、`PendingState`…）

后果：**改一个域的端点，无法判断会影响谁**；想按域拆开时，每个域都会反过来 import `api.ts`
去拿常量和类型，立刻成环（架构断言的环检查会直接失败）。

第一次尝试"一次搬五个域"，被依赖网打断、整体回滚——教训是**顺序错了**。

## 决定

分两步，**顺序不能颠倒**：

**第一步：建中间层（不依赖 api.ts）**

| 模块 | 内容 |
|---|---|
| `mobile-types.ts` | 所有跨端点共享类型（47 个）。谁都不依赖，所以谁都能依赖它 |
| `data/limits.ts` | 时限常量（**只搬 `const`**） |
| `data/read-coalescing.ts` | 只读合并窗口（并发共享 + 1.2s 复用 + 写后失效） |
| `data/workspace-roster.ts` / `observe-latch.ts` | 原来的 `let` 可变状态 → **访问器函数** |
| `data/chat-helpers.ts` | 被域实现共用的纯函数与常量 |

**第二步：按依赖从少到多，一次搬一个域，搬完立刻 typecheck**

`voice → notify → fs → workspace → settings → session`

结果：`api.ts` 1,488 → **186 行**，八个域全部 ≤400 行，对外 API 一个没变（`api.ts` 只保留
re-export），调用点零改动。

### 两条硬约束（踩出来的）

1. **`let` 不能跨模块搬**：ES 模块导入绑定不可赋值（TS2632）。可变状态必须包成
   `getX()/setX()`。
2. **`export type { … } from` 不会把名字带进本文件作用域**：本文件里还用到这些类型时，
   必须再 `import type` 一次，否则 TS2304。这个坑犯了三次。

## 代价

- **多了一层间接**：找"这个端点在哪个文件"要经过 `api.ts` 的 re-export 转出。用 IDE 的
  "跳转到定义"不受影响，但读代码的人要先知道规则。
- **中间层会膨胀**：`mobile-types.ts` 已经 500 行、47 个类型。**再大就该按域再分**，
  这是下一次的技术债。
- **`api.ts` 变成"什么都转"的桶**：它现在没有逻辑，但也没了内聚性。好处是**它不再是热点**
  ——冲突基本消失。
- **域边界是经验性的**：`settings` 里混着设备管理，`fs` 里混着附件上传。按业务域切不可能
  完全干净，只能保证"改一个域时不需要动另一个域的文件"。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 保留 `api.ts`，只按注释分段 | 1,488 行文件里靠注释分段等于没有边界；改动的 review 无法按域分配 |
| 先拆函数再拆状态 | 试过，正是被依赖网打断的那次；状态必须先有家 |
| 用依赖注入容器统一提供状态 | 移动端只有几份状态，容器带来的间接成本高于收益 |
