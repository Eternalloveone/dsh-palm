# dsh-palm 重构总方案（2026-11-08 版）

> 本文是**总纲**，只讲做什么、按什么顺序、怎么验收。
> 细节见：`mobile-design-spec.md`（UI 定版）· `target-architecture-v3.2.md`（架构）· `layout-contract.md`（布局契约）· `native-feel-plan.md`（交互）。

---

## 一、四个目标

| # | 目标 | 一句话验收 |
|---|---|---|
| 1 | **能维护** | 每个文件有明确职责与行数上限，超了脚本报红 |
| 2 | **能换皮** | 换一套皮肤只改令牌，不改任何组件 |
| 3 | **能换布局** | 换排布只加一个 layout 文件，不动业务逻辑 |
| 4 | **好用** | 打开就是对话，1 步到产物，0 手势冲突 |

## 三、目标分层

```
app/            壳：路由、页面栈、布局装配            ≤ 400 行/文件
  shell.tsx
  host-bridge/  订阅、状态、动作                     ≤ 600 行/目录
features/<屏>/  18 个屏幕，每屏 = 容器 + 组件 + 槽位
  *.slots.ts    插槽类型（契约）
  layouts/      排布（纯数据）
components/     业务组件（只吃 props/context）
ui/             机制件：overlay/sheet/menu/focus-trap/slot-layout
render/         折叠模型、结论卡、diff 渲染
design/         tokens.css / components.css / skins
```

**四条契约**（越界即断言红）：

| 契约 | 形式 | 断言 |
|---|---|---|
| 模型切片 | 每屏一个 zod schema | 视图层禁止直接读 api |
| 动作 | `types/actions.ts`，只吃 props | `components/` 不得 import 实现 |
| 插槽 | `*.slots.ts` 类型 + layout 数据 | 必填槽恰好用一次；layout 零 hook |
| 皮肤 | `tokens.<skin>.css` + 覆盖文件 | 皮肤不得新增类名；`@layer` 顺序固定 |

## 四、五层可换（成本递增）

| 层 | 换什么 | 加一套成本 |
|---|---|---|
| L1 令牌 | 颜色/间距/字号/圆角 | 2 个 CSS 文件（1–2h） |
| L2 组件形态 | 圆角/字重/密度/描边 | 半天 |
| L3 布局 | 区块排布（谁在上、谁并排） | 1 个 layout 文件（0.5–1 天） |
| L4 视图 | 结构与交互不同 | 1 个新实现（1–3 天） |
| L5 交互 | 转场/手势/反馈 | 内核一次到位（4 天） |

已定皮肤：**石墨 / 纸 / 夜航**（见 UI 定版规范）。

## 五、阶段与工时

| 阶段 | 内容 | 产出 | 天 |
|---|---|---|---|
| **P0 地基** | 断言引擎升级为 TS 模块图（消除正则盲区）；预算曲线（单文件 + 全目录）；golden 冻结与退出条件 | 门禁可信 | 2.0 |
| **P1 设计系统** | `tokens.css` + `components.css` 落成（令牌/卡片 3 级/按钮 4 型 6 态/图标集）；三套皮肤 | 样式可复用 | 1.5 |
| **P1.5 布局契约** | `slot-layout.tsx` + `types/layout.ts` + 5 条断言 + 9 屏默认 layout | 排布可换 | 2.0 |
| **P2 壳** | 页面栈路由 + `host-bridge`（单一订阅点）+ 18 屏路由表 | 导航可跑 | 3.0 |
| **P3 屏幕迁移** | 18 屏按定版规范迁（先 ①③④⑪，再其余） | 全站新 UI | 8.0 |
| **P4 交互内核** | 转场双缓冲 + 触感/骨架 + 安全区收口 | 接近原生手感 | 4.0 |
| **P5 清账** | 拆 `mobile-api.ts` 到 `api/*.ts`（≤800 行/文件）；删旧样式；文档归档 | 无历史包袱 | 3.0 |
| | | **合计** | **23.5 天** |

**顺序理由**：P0 保证后面每一步"变坏能被发现"；P1/P1.5 是后面所有屏的地基；P5 放最后，避免边拆边改。

## 六、每步的验收门（缺一不可）

```powershell
pnpm typecheck        # 类型
pnpm build            # 构建
pnpm test             # 全量测试（不得低于当前基线）
$env:PALM_BASE='http://127.0.0.1:3099'; node tools/health-check.mjs
node tools/mobile-visual/run.mjs      # 9 屏视觉门禁
git diff --stat                        # 预算检查
```

**三条铁律**：每个切片结束必须全绿；**只降不升**行数预算；任何门禁不得放宽（只能加严或有据豁免 + 到期日）。

## 七、明确不做

| 不做 | 原因 |
|---|---|
| React 升级 / Tailwind / Radix / vaul / 状态库 / 虚拟列表 | 现有依赖够用，换库收益低风险高 |
| Vite / 单包拆多包 / monorepo | 构建已稳定，拆分只会增加维护面 |
| CSS-in-JS | 与"禁 JS 计算样式"冲突 |
| 抽屉 / 底部弹层 / 自定义滑动手势 | 与 iOS 边缘返回、上滑回主屏抢手势 |
| 运行时切布局 | 先构建期，运行时列为重估项 |
| 桌宠 / 吉祥物 | 差异点但不解决问题，优先级最低 |

---

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 18 屏迁移量大，中途停滞 | 按屏切片，每片独立可上线；①③④⑪ 先做（覆盖 80% 使用） |
| 视觉门禁误报（曾连红 4 次） | 门禁只在构建完成后跑；一次性浮层加入白名单 |
| 拆 `mobile-api.ts` 破坏测试 | 先加"导出面等价"断言，再拆 |
| 皮肤机制拖慢首屏 | 皮肤 CSS 构建期生成，运行时不计算样式 |
| 预算被逐步突破 | 单文件 + 全目录双曲线，只降不升 |
