# dsh-palm 全项目重构方案（2026-11-08 定稿）

> 范围：**工程基座 + 服务层 + 状态/渲染 + UI 架构 + 交互层**，不只是界面。
> 配套文档：`mobile-design-spec.md`（UI 定版）· `target-architecture-v3.2.md`（架构评估）· `layout-contract.md`（布局契约）· `native-feel-plan.md`（交互）。

---

## 一、项目现状盘点

| 维度 | 现状 | 问题 |
|---|---|---|
| 形态 | 单个 npm 包 `@eternalloveone/dsh-palm` v1.7.1，tsdown + lightningcss 构建 | 无 |
| 手机端入口 | `/m/` 路由 + `src/mobile/index.tsx` | — |
| `src/mobile-api.ts` | **3,848 行**，两张分发表（`localHandlers` ~1215、`methods` ~3086） | 单文件承担全部 RPC，改一处要读全文件 |
| 屏幕层 | 9 屏 10,309 行；`ChatView` 4,138 行 | 视图层同时做取数、订阅、计算、渲染 |
| 订阅 | 20 个 `useEffect` + 45 个 hook 散在视图层 | 无单一订阅点，难测 |
| CSS | 42 源文件 → 生成 9,378 行；876 类名；**无 `@layer`** | 层叠顺序靠 import 顺序，改样式易连带 |
| 令牌 | `design/tokens.ts` 有明暗两套；桌面端 9 处偏差 | 手机/桌面不一致 |
| 断言 | 14 条，实现为 `readFileSync` + 正则（已知 4 个盲区：动态 import、`export *`、别名、`import type`） | 守不住真实依赖关系 |
| 反馈回路 | 只有本地 `tools/health-check.mjs`；无 CI、无 lint 脚本 | 破坏靠人肉发现 |
| 测试 | 有 golden（`tests/golden/chat-trace.json`）、视觉门禁、全量单测 | 结构类断言弱 |
| 性能 | 有 `tools/mobile-perf`、视觉基线 | 无 SLO，无回归告警 |

## 二、目标架构（一张图）

```
┌──────────────────────────────────────────────┐
│ app/          壳：页面栈路由、布局装配、错误边界   ≤400 行/文件
│  ├ shell.tsx                                 │
│  └ host-bridge/  订阅·状态·动作                ≤600 行/目录
├──────────────────────────────────────────────┤
│ features/<屏>/  18 个屏幕                      │
│  ├ <屏>.slots.ts     插槽契约（类型）           │
│  ├ <屏>.layout.tsx   布局数据 → 插槽            │
│  └ layouts/*.ts      排布方案（纯数据）          │
├──────────────────────────────────────────────┤
│ components/     业务组件（只吃 props/context）   │
│ render/         折叠模型·结论卡·diff·流式        │
│ ui/             机制件：overlay/sheet/menu/…     │
├──────────────────────────────────────────────┤
│ data/           模型切片（zod schema）           │
│ api/            服务端：sessions/chat/settings… ≤800 行/文件
│ design/         tokens.css·components.css·skins │
└──────────────────────────────────────────────┘
```

**依赖方向唯一**：`app → features → components → ui`，`features → data`，`data → api`。**反向零容忍**。

## 三、六个重构域

| 域 | 内容 | 关键动作 |
|---|---|---|
| **A 工程基座** | 构建、测试、门禁、预算 | 断言引擎换 TS 模块图；预算曲线（单文件 + 全目录）；lint 脚本补齐 |
| **B 服务层** | `mobile-api.ts` 拆解 | 按域拆 `api/{sessions,chat,settings,workspace,search}.ts`；先加"导出面等价"断言再拆 |
| **C 状态/数据流** | 订阅与模型切片 | `host-bridge` 单一订阅点（`useSyncExternalStore`）；每屏一个 zod 切片 |
| **D 渲染层** | 折叠、结论卡、diff、流式 | 结论卡四态组件；过程折叠规则；diff 渲染独立 |
| **E UI 架构** | 令牌、组件、皮肤、布局契约 | `tokens.css`/`components.css`；三皮肤；`slot-layout` + 5 条断言；18 屏 |
| **F 交互层** | 路由、转场、反馈 | 页面栈（零手势）；转场双缓冲；骨架屏与乐观更新 |

## 四、依赖顺序

```
A 工程基座 ──┬─→ B 服务层 ──→ C 状态/数据流 ──→ D 渲染 ──→ E UI ──→ F 交互
             └─→ E1 令牌/组件（可与 B 并行，互不阻塞）
```

- **A 必须最先**：后面每一步"变坏"要被自动发现。
- **B 与 E1 可并行**：一个改服务端，一个改样式，文件不重叠。
- **C 在 B 之后**：切片依赖稳定的数据形状。
- **F 最后**：转场依赖稳定的路由与页面结构。

## 八、明确不做

| 不做 | 原因 |
|---|---|
| React 升级 / Tailwind / Radix / vaul / 状态库 / 虚拟列表 | 收益低、风险高，现有依赖够用 |
| Vite / Rolldown / 拆多包 / monorepo | 构建已稳定，拆分只增维护面 |
| CSS-in-JS | 与"禁 JS 计算样式"冲突 |
| 抽屉 / 底部弹层 / 自定义滑动手势 | 与 iOS 边缘返回、上滑回主屏抢手势 |
| 运行时切布局 | 先构建期，运行时列为重估项 |
| 桌宠 / 吉祥物 | 差异点但不解决问题 |

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| P2 拆 API 破坏测试 | 先加"导出面等价"断言，再逐域拆；每域一提交 |
| P6 18 屏迁移停滞 | ①③④⑪ 先做（覆盖 80% 使用），其余按使用频率排队 |
| 视觉门禁误报（曾连红 4 次） | 门禁只在构建完成后跑；一次性浮层进白名单 |
| 预算被逐步突破 | 双曲线 + 只降不升 + CI 拦截 |
| 皮肤拖慢首屏 | 皮肤 CSS 构建期生成，运行时不计算样式 |
