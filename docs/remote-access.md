# 手机怎么访问到这台机器

手机要能打开 `http://<你的地址>:<端口>/m/`，才算装好。三条路，按你的实际情况选一条。

## 一、同 Wi-Fi（30 秒，够用）

手机和电脑连同一个路由器即可。打开桌面侧边栏的手机图标，面板会给出它探测到的局域网地址，直接用。

适合：在家里 / 办公室随手用。不适合：想在外面用、或者路由器开了客户端隔离。

## 二、Tailscale（5 分钟，推荐）

两台设备都装 Tailscale 并登录同一账号。配对面板会认出你的 tailnet 域名，一键应用。

适合：想在外面稳定用、又不想把端口暴露到公网。

## 三、frp / Cloudflare Tunnel（已有就 1 分钟）

面板可以直接填隧道地址，**保存前会先探测可达性**，填错了当场拦住。

- **frp + nginx TLS**：推荐。有受信证书，PWA 能装，延迟接近直连
- **Cloudflare Tunnel**：兜底。国内绕道，延迟约 20–30 倍

详细步骤（含 frps/nginx/frpc 完整拓扑、验证、FAQ）见 [remote-access-guide](../../packages/dsh-palm/docs/remote-access-guide.md)。

## 配完怎么配对

面板是「配置 → 配对 → 使用」三步：

1. **配置**：填手机能访问到的地址，保存会先探测
2. **配对**：手机扫码，或手输面板上的 6 位码（一次性，默认 10 分钟过期，重新生成即失效）
3. **使用**：已配对的设备列表，可单独撤销

## 安全铁律（别省）

| 不要 | 为什么 |
|---|---|
| 不要用 `tailscale funnel` 暴露 | 等于把宿主挂公网 |
| 不要 `--host 0.0.0.0` 裸跑 | 任何能连到端口的人都是管理员 |
| 公网/隧道入口不要加 `--trusted-host` | 会绕过 `/api` 的 fence，配对 cookie 直接升级为全权 |
| 只配受信域名 | 例如你的 tailnet 域名或带正式证书的域名 |

配对 cookie 存在 `$DSH_HOME/dsh-palm-devices.json`。撤销设备后，那台手机立刻失效，需要重新扫码。

## 实测延迟（2026-09，国内客户端，20 次顺序请求）

| 接入方式 | 最小 | P50 | P95 | 最大 |
|---|---|---|---|---|
| 本机回环 | 1 ms | 2 ms | 4 ms | 9 ms |
| frp 直连（HTTP） | 10 ms | 14 ms | 27 ms | 35 ms |
| nginx TLS（受信证书） | 13 ms | 15 ms | 24 ms | 57 ms |
| Cloudflare Tunnel | 405 ms | 413 ms | 463 ms | 1209 ms |

复现：`scripts/measure-paths.mjs`（URL 由参数或 `DSH_PALM_PATHS` 传入）。

## 打不开怎么排

| 现象 | 先查 |
|---|---|
| 手机浏览器超时 | 手机连的是不是同一网络；路由器有没有"客户端隔离" |
| 电脑能开、手机不能 | 防火墙是否放行该端口 |
| 页面开了但装不了 PWA | 必须是 HTTPS（受信证书）；`http://` 只能是局域网临时用 |
| 扫码后没反应 | 面板地址和手机实际访问的地址是否一致（改过端口要重新生成二维码） |
| 配对成功但一直转圈 | 宿主是否重启过；撤销设备后要重新扫 |
